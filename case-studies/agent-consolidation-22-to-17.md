## 1. 숫자 역산 (실측)

`22 → 17`은 파일 개수가 아니라 **운용 에이전트 수**다. 파일만 세면 어긋난다.

| 구분 | `agents/*.md` (템플릿 제외) | `agents/` 밖 | 합계 |
|------|------|------|------|
| 통폐합 직전 | **21** | +1 | **22** |
| 통폐합 직후 | **16** | +1 | **17** |
| 현행 | **16** | +1 | **17** |

- `agents/` 밖 +1 = 독립 세션 에이전트. 정의가 별도 경로의 `CLAUDE.md`에 있어
  `agents/` 디렉토리에는 파일이 없지만, 위임 테이블에는 등재되어 있어 카운트에 포함된다.
- 검증: `git ls-tree --name-only {commit}^ .claude/agents/` = 21 / `{commit}` = 16 / 현행 `ls` = 16
  (통폐합 이후 `agents/` 파일 변동 0건, diff 공집합)
- 5개는 **삭제가 아니라 `R100` rename**(내용 100% 동일)으로 이동 → 원본 그대로 복원 가능

> 숫자를 보고할 때는 그 숫자가 무엇을 세는지부터 정의한다.
> "22→17"만 적어두면 나중에 파일 개수와 안 맞아서 아무도 검증하지 못한다.

## 3. 폐지 ≠ 삭제

처분이 네 가지로 갈린다는 점이 중요하다.

| 처분 | 의미 | 복원 |
|------|------|------|
| 스킬로 강등 | 애초에 에이전트가 아니었어야 함 | **복원 금지** |
| 통합 | 역할이 다른 곳으로 흡수됨 | 흡수처에서 분리 필요 |
| 휴면 | 영역은 살아있으나 트래픽이 0 | 그대로 복원 |
| 삭제 | — | (실제로 쓴 적 없음) |

## 4. 복원 절차

1. `git mv agents_archived/{name}.md agents/`
2. 위임 테이블 + 에이전트 정의 목록에 행 복구
3. **흡수처 에이전트에서 중복 역할 제거** — 이 단계를 빼면 두 에이전트가 같은 일을 하게 된다
4. 신설 프로토콜 준용 — owner 승인 필요

★ **스킬로 강등된 것은 복원 대상이 아니다.**
스킬이 정식 경로이고, 되살리면 "툴/스킬 우선" 원칙 위반 + 중복 재발이다.

## 5. 이 케이스에서 남는 교훈

1. **폐지 시점에 사유를 파일에 적는다.** 안 적으면 3개월 뒤 역산해야 한다. 실제로 그랬다.
2. **숫자는 정의부터.** 무엇을 세는 숫자인지 먼저 못 박는다.
3. **rename으로 접는다.** 삭제하면 복원 경로가 사라진다.
4. **"복원 금지" 항목을 명시한다.** 안 적으면 언젠가 누군가 되살린다.
